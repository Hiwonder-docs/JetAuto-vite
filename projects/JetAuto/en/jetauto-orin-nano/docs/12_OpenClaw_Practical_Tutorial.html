12. OpenClaw Practical Tutorial ​

NOTE

The robot is pre-configured with OpenClaw and related function packages at the factory. For the first run, follow Section 12.1 Preparation to import and compile the resources. If errors or incompatibilities occur when running applications according to the tutorial later, follow Section 12.1 Preparation to re-import the provided backup resource files and skills into the corresponding paths and compile. After successful compilation, proceed with the application tutorials.

12.1 Preparation ​

Before running any applications, move the OpenClaw resource files to the corresponding folders.

  1. Use NoMachine to connect remotely to the robot and enter the system desktop.
  2. Drag the openclaw_resource.zip file from the OpenClaw resource folder to the desktop.
  1. Click the command-line terminal icon on the left side of the system desktop to open a terminal.
  2. Enter the following command to extract the file to the corresponding path.
bash
unzip ~/Desktop/openclaw_resource.zip -d .
  1. Enter the following command to enter the folder.
bash
cd openclaw_resource
  1. Enter the following command to execute the deployment script.
bash
zsh deploy.sh
  1. Enter y for all subsequent options.

  1. After the script runs, the previous IDENTITY.md, MEMORY.md, and skills backups are saved in the backup.20260408_111805 folder. Use the ls command to view them.

  2. Enter the following commands in the terminal to enter the workspace and compile the openclaw_controller package.

bash
cd ~/ros2_ws/ && colcon build --event-handlers console_direct+ --cmake-args -DCMAKE_BUILD_TYPE=Release --symlink-install --packages-select openclaw_controller
  1. After compilation finishes, enter the following command to refresh the environment variables.
bash
source ~/.zshrc

12.2 Large Language Model API Key Acquisition and Configuration ​

When using OpenClaw on the robot, configure the agent model in the Agent first. Obtain the large language model API key and fill it into the corresponding configuration file.

OpenClaw supports multiple large language models, such as DeepSeek, MiniMax, OpenAI, Qwen, and Google. This section uses OpenAI as the configuration example. For other models, search online for the corresponding API key configuration method and apply it to the file.

12.2.1 OpenAI Large Model API-Key Acquisition ​

NOTE

This section requires registration on the official OpenAI website to obtain the large model key.

  1. Copy the URL: https://platform.openai.com/docs/overview, open the OpenAI webpage, and click Register in the upper right corner.
  1. Follow the prompts to register and log in using Google, Microsoft, or Apple accounts.
  1. Click the Settings button, then click Billing, and click Payment methods to bind a payment method. Recharge to purchase tokens.
  1. After completing the preparations, click API keys, click Create secret key, fill in according to the prompts, and save the key after applying for later use.
  1. At this point, the creation and deployment of the large model are complete. This API will be used in subsequent courses.

12.4.1.4 Program Analysis ​

Program path:

/home/ubuntu/ros2_ws/src/openclaw_controller/openclaw_controller/robot_base_control/claw_move_control.py

  1. Initialize three parameters (linear velocity, angular velocity, and stop duration). Create a chassis control node that receives string motion commands, places the commands into a queue, processes them with a background thread, and finally publishes velocity control messages. A motion status query service is also provided.
python
        self.default_linear = 0.15
        self.default_angular = 0.45
        self.default_stop_duration = 0.5

        self.cmd_vel_pub = self.create_publisher(Twist, '/controller/cmd_vel', 1)
        self.subscription = self.create_subscription(
            String, '~/chassis_command', self.command_callback, 10)
        self.move_status = 'stop'
        self.create_service(Trigger, '~/move_status', self.move_status_srv_callback)

        self.command_queue = queue.Queue()
        self.client = self.create_client(Trigger, '/init_pose/init_finish')
        self.client.wait_for_service()
        self.worker_thread = threading.Thread(target=self.process_commands, daemon=True)
        self.worker_thread.start()
  1. When an external request is received to view the current motion status, this function prints self.move_status and returns it through the service response.
python
    def move_status_srv_callback(self, request, response):
        self.get_logger().info('\033[1;32m Move status: [%s]\033[0m' % self.move_status)
        response.success = True
        response.message = self.move_status
        return response
  1. This function generates the corresponding chassis velocity control message Twist according to the input direction string and updates the robot motion status.
python
    def parse_twist(self, direction):
        twist = Twist()
        self.move_status = 'moving'
        if direction == 'forward':
            twist.linear.x = self.default_linear
        elif direction == 'backward':
            twist.linear.x = -self.default_linear
        elif direction == 'left':
            twist.linear.x = self.default_linear
            twist.angular.z = self.default_angular
        elif direction == 'right':
            twist.linear.x = self.default_linear
            twist.angular.z = -self.default_angular
        elif direction == 'stop':
            pass
        else:
            return None
        return twist
  1. This function receives the subscribed string command, cleans and validates it, prints a log, and then places it into the command queue to wait for background thread processing.
python
    def command_callback(self, msg):
        cmd = msg.data.strip()
        if not cmd:
            return
        self.get_logger().info(f'\033[1;34m Command: {cmd}\033[0m')
        self.command_queue.put(cmd)
  1. This function continuously takes pending commands from the command queue and calls the execution function in sequence for processing.
python
    def process_commands(self):
        while rclpy.ok():
            try:
                cmd = self.command_queue.get(timeout=0.5)
            except queue.Empty:
                continue
            self.execute_command(cmd)
            self.command_queue.task_done()
  1. This function parses a string compound motion command, executes multiple chassis motion actions in sequence, and stops the robot when execution ends or an error occurs.
python
    def execute_command(self, cmd):
        try:
            cmd = cmd.replace('，', ',')
            parts = [p.strip() for p in cmd.split(',') if p.strip()]
            actions = []
            self.move_status = 'moving'
            for p in parts:
                w = p.split()
                dir = w[0].lower()
                dur = float(w[1]) if len(w) > 1 else self.default_stop_duration
                actions.append((dir, dur))
            
            for i, (dir, dur) in enumerate(actions):
                twist = self.parse_twist(dir)
                if twist is None:
                    self.get_logger().error(f'\033[91mUnknown direction: {dir}\033[0m')
                    self._stop()
                    return
                self.cmd_vel_pub.publish(twist)
                time.sleep(dur)
                if i < len(actions) - 1:
                    self._stop()
                    time.sleep(self.default_stop_duration)
            self._stop()
            self.get_logger().info(f'\033[1;33m Command done\033[0m')
        except Exception as e:
            self.get_logger().error(f'Execution error: {e}')
            self._stop()

12.4.2.4 Program Analysis ​

Program path:

/home/ubuntu/ros2_ws/src/openclaw_controller/openclaw_controller/robot_base_control/claw_arm_group_control.py

  1. Initialize an arm action group control node to receive action group commands, control the servos to execute preset actions, provide an arm status query service, and wait for the initial pose service to be ready before startup.
python
        self.controller = ActionGroupController(
            self.create_publisher(ServosPosition, 'servo_controller', 1),
            '/home/ubuntu/software/arm_pc/ActionGroups'
        )
        
        self.subscription = self.create_subscription(
            String,
            '~/arm_group_control',
            self.command_callback,
            10
        )

        self._execution_lock = threading.Lock()
        self._is_executing = False
        self.arm_status = 'stop'
        self.create_service(Trigger, '~/arm_group_status', self.arm_group_status_srv_callback)
        self.supported_actions = ['voice_pick', 'voice_give', 'init', 'camera_up']

        signal.signal(signal.SIGINT, self.shutdown)
        self.client = self.create_client(Trigger, '/init_pose/init_finish')
        self.client.wait_for_service()
  1. When an external request is received to view the current motion status, this function prints self.arm_status and returns it through the service response.
python
    def arm_group_status_srv_callback(self, request, response):
        self.get_logger().info('\033[1;32mArm status: [%s]\033[0m' % self.arm_status)
        response.success = True
        response.message = self.arm_status
        return response
  1. This function receives the arm action command, checks whether the arm is currently busy and whether the command is valid. If execution is possible, set the arm status to running and start a new thread to execute the action.
python
    def command_callback(self, msg):
        cmd = msg.data.strip()
        if not cmd:
            return
        
        self.get_logger().info(f'\033[1;34mCommand received: {cmd}\033[0m')
        
        with self._execution_lock:
            if self._is_executing:
                self.get_logger().warn(f'\033[93mBusy, ignoring command: {cmd}\033[0m')
                return
        
        if cmd not in self.supported_actions:
            self.get_logger().error(f'\033[91mUnsupported action: {cmd}\033[0m')
            return

        with self._execution_lock:
            self._is_executing = True
        self.arm_status = 'moving'
        threading.Thread(target=self.execute_action, args=(cmd,), daemon=True).start()
  1. This function executes the specified arm action group command. After successful execution, update the status and print a completion log. If execution fails, record the error. Regardless of success or failure, release the "executing" flag at the end.
python
    def execute_action(self, cmd):
        try:
            self.controller.run_action(cmd)
            self.arm_status = 'finished'
            self.get_logger().info(f'\033[1;32mAction {cmd} completed\033[0m')
        except Exception as e:
            self.get_logger().error(f'\033[91mError executing {cmd}: {e}\033[0m')
        finally:
            with self._execution_lock:
                self._is_executing = False

12.5.1.5 Step-by-Step Debug ​

NOTE

If OpenClaw does not successfully run the program after entering a text command in the tui window, enter commands step by step for testing to observe which step produces an error message.

  1. Open a terminal and enter the following command to start the application:
bash
ros2 launch openclaw_controller smart_scene_navigation.launch.py navigation_mode:="smart_community"
  1. Open a new terminal and enter the following command to query the navigable waypoints and their IDs.
bash
ros2 service call /claw_navigation_manager/list_positions std_srvs/srv/Trigger {}
  1. Publish the navigation point according to the queried ID to navigate to the express station The data is the ID value of the express station to be passed:
bash
ros2 topic pub /request_waypoint std_msgs/msg/Int32 "data: 17" --once
  1. Grasp cola:
bash
ros2 service call /apriltag_control_node/pick_drink std_srvs/srv/Trigger "{}"
  1. Publish the navigation point according to the queried ID to navigate to the supermarket. The data is the ID value of the supermarket to be passed:
bash
ros2 topic pub /request_waypoint std_msgs/msg/Int32 "data: 15" --once
  1. Place cola:
bash
ros2 service call /apriltag_control_node/place_drink std_srvs/srv/Trigger "{}"
  1. Navigate home
bash
ros2 topic pub /request_waypoint std_msgs/msg/Int32 "data: 0" --once
  1. Clear the AprilTag target point:
bash
ros2 service call /apriltag_control_node/clear_target std_srvs/srv/Trigger "{}"
